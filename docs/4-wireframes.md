# 색연필 색소폰 동호회 홈페이지 - 와이어프레임

## 0. 문서 개요
본 문서는 도메인 정의서(`1-domain-definition.md`), PRD(`2-PRD.md`), 사용자 시나리오(`3-user-scenario.md`)를 기반으로 주요 화면의 레이아웃을 ASCII 박스 다이어그램으로 정리한다. 실제 디자인 시스템/색상/타이포그래피는 다루지 않으며, 화면 구성요소와 관련 기능ID 확인용 참고 자료로 사용한다.

**배치의 단일 출처는 이 문서의 ASCII 다이어그램이다.** 설계 단계에서는 화면별 SVG 도면 18개를 `docs/wireframes/` 하위에 함께 두었으나(`02-home.svg` 형태, 모바일은 `-mobile` 접미사), **구현이 끝난 뒤 이 디렉토리를 삭제했다.** 도면 내용은 최초 설계 커밋(`0147524`)에 남아 있으므로 필요하면 그 시점에서 꺼내 볼 수 있다 — 여기에 커밋 해시를 적는 이유는 지금 트리에 없는 파일을 가리켜야 하기 때문이다(문서 관리 원칙 §8의 예외 조항).

삭제한 이유는 도면이 설계 시점 배치에서 갱신되지 않아 구현과 어긋났기 때문이다 — 6번(등급 표기), 7번(페이지네이션), 14번(예약 현황의 위치)이 특히 다르다. 구현이 끝난 뒤 실제 배치를 확인할 곳은 실행되는 화면과 이 문서이므로, 손으로 그린 SVG를 세 번째 사본으로 유지하면 어긋난 사본이 하나 더 생길 뿐이다. 따라서 **새 화면을 그릴 때 SVG를 만들지 않으며, 이 문서의 다이어그램만 갱신한다.**

화면의 색·타이포까지 입힌 확정 시안은 `docs/designs/`에 HTML로 보관하며, 2번 홈 화면(`docs/designs/02-home.html`) 1건이다(`9-style.md` §7).

**구현 반영**: 아래 다이어그램은 FE-01~09에서 실제로 구현된 화면과 일치하도록 갱신되어 있다. 구현과 최초 설계가 달라진 곳은 각 화면 설명의 "구현 결과" 항목에 적었다.

## 1. 공통 사항

### 화면번호 ↔ 라우트 경로 (구현 결과)
화면 번호는 `frontend/src/App.tsx`의 라우트와 아래와 같이 대응한다. 경로의 단일 출처는 `App.tsx`이며, 이 표는 그 결과를 옮긴 것이다.

| 화면 | 경로 | 컴포넌트 | 접근 |
|---|---|---|---|
| 2. 홈 | `/` | `HomePage` | 공개 |
| 3. 회원가입 | `/signup` | `SignupPage` | 공개 |
| 4. 로그인 | `/login` | `LoginPage` | 공개 |
| 5. 마이페이지 | `/me` | `MyPage` | 로그인 |
| 6. 게시판 목록 | `/boards` | `BoardListPage` | 로그인 |
| 7. 게시글 목록 | `/boards/:boardId/posts?page=` | `PostListPage` | 로그인 |
| 8-1. 게시글 작성 | `/boards/:boardId/posts/new` | `PostFormPage` | 로그인 |
| 8-1. 게시글 수정 | `/posts/:postId/edit` | `PostFormPage` | 로그인 |
| 8-2. 게시글 상세 | `/posts/:postId` | `PostDetailPage` | 로그인 |
| 9. 연습실 예약현황 | `/practice-rooms?roomId=&date=` | `PracticeRoomPage` | 로그인 |
| 10. 예약 신청 | `/practice-rooms/:roomId/reserve?date=&start=&end=` | `ReservationConfirmPage` | 로그인 |
| 11. 내 예약 내역 | `/me/reservations?roomId=` | `MyReservationsPage` | 로그인 |
| 12. 회원 등급 관리 | `/admin/members?q=` | `MemberGradeAdminPage` | 관리자 |
| 13. 게시판 관리 | `/admin/boards` | `BoardAdminPage` | 관리자 |
| 14. 연습실 관리 | `/admin/practice-rooms` | `PracticeRoomAdminPage` | 관리자 |

와이어프레임에 없으나 구현된 화면이 둘 있다.

- **관리자 입구** (`/admin`, `AdminHomePage`): 12·13·14번으로 가는 링크 3개만 둔 목록 화면이다. 상단 네비게이션의 [관리자] 메뉴가 관리자 화면 3개를 한꺼번에 가리킬 수 없어 입구를 하나 두었다.
- **없는 경로** (`*`, `NotReadyPage`): 주소를 잘못 입력했을 때의 404 화면이다.

목록·필터·페이지·검색어 같은 화면 상태는 컴포넌트 안이 아니라 위 표처럼 **주소(query string)에 둔다** — 새로고침·뒤로가기·링크 공유가 그대로 동작해야 하기 때문이다.

### 공통 규칙
- 상단 공통 네비게이션(로고, 게시판, 연습실 예약, 마이페이지, 로그인/로그아웃, [관리자] 메뉴 - 관리자 등급에만 노출)을 모든 화면에서 공유한다.
- **반응형 규칙(요약)**:
  - 폼 위주 화면(회원가입/로그인/마이페이지/예약 신청 등)은 PC/모바일 모두 1열 레이아웃이라 폭만 좁아질 뿐 구성은 동일하다. 별도 모바일 와이어프레임은 생략한다.
  - 표(테이블) 위주 화면(게시글 목록, 연습실 예약현황, 내 예약 내역 등)은 모바일에서 표를 그대로 축소하지 않고 **행 단위 카드 리스트**로 전환한다. 아래 각 화면에 모바일 버전을 별도로 표기한다.
  - 상단 네비게이션은 모바일에서 햄버거(≡) 아이콘 안으로 축소된다.
  - 관리자 화면은 회원 수(500명 이하) 규모상 주로 PC에서 운영된다고 가정하고, 모바일에서는 표를 가로 스크롤로 그대로 보여주는 것으로 충분하다(별도 모바일 와이어프레임 생략).

## 6. 게시판 목록 화면 (S-03, F-10)

```
+--------------------------------------------------+
| 색연필   [게시판] | 연습실예약 | 마이페이지 | 로그아웃 |
+--------------------------------------------------+
|                게시판 목록                         |
|                                                    |
|  [자유게시판]        이용 가능                     |
|  [공지사항]          이용 가능                     |
|  [정회원 게시판] 🔒   접근불가 · 최소등급 20 필요   |
|  [운영진 전용] 🔒     접근불가 · 최소등급 30 필요   |
|                                                    |
|  ※ 내 등급: 준회원 (등급 10)                       |
+--------------------------------------------------+
```
- 핵심 요소: 게시판별 이용가능 최소등급 표시, 내 등급으로 접근 불가한 게시판은 잠금 아이콘/비활성 표시. 클릭 시 서버에서도 등급 재검증.
- **구현 결과**: 최소등급을 "정회원 이상"처럼 **등급명이 아니라 서열 숫자로 표기**한다(`접근불가 · 최소등급 20 필요`). 게시판 목록 API(`GET /api/boards`)가 `minGradeLevel`(정수)만 주고, 서열→등급명 변환에 필요한 등급 목록은 관리자 전용(`GET /api/admin/member-grades`)이어서 일반 회원 화면에서 이름을 얻을 방법이 없다. 내 등급명은 `GET /api/members/me`가 주므로 하단 안내에는 이름과 숫자를 함께 적는다.
- **구현 결과**: 접근 불가 게시판도 링크로 남겨 둔다. 잠금 표시는 예고일 뿐이고 실제 거절 문구는 진입 시 서버 403이 내려주는 것을 그대로 보여준다(등급 판정을 프론트에서 다시 계산하지 않는다).
- 관련 기능: F-10

- 모바일: 표 대신 게시글 1건당 1개 카드(제목+메타정보 2줄)로 표시.
- **구현 결과**: 페이지네이션은 페이지 번호를 나열하지 않고 `[이전] 현재/마지막 [다음]`으로 구현했다. 목록 API가 `totalCount`·`page`·`pageSize`를 주므로 마지막 페이지는 계산할 수 있지만, 번호 링크를 나열하면 페이지가 많아질 때 생략(`1 … 7 8 9 … 20`) 규칙이 필요해져 얻는 것보다 코드가 커진다. 현재 페이지는 주소(`?page=`)에 둔다.

- 핵심 요소: 연습실 등록/수정/삭제 및 사용여부 처리, 예약 현황/내역 조회, 관리자는 시작 여부와 무관하게 예약 강제취소 가능.
- **구현 결과**: 예약 현황·내역은 **별도 화면으로 나누지 않고 연습실 관리 화면(`/admin/practice-rooms`) 아래쪽 섹션**으로 뒀다. 관리자가 연습실을 비활성으로 바꾸거나 삭제하려면 그 연습실의 예약을 함께 봐야 하므로(예약이 있으면 삭제가 409로 거부된다) 두 화면을 오가는 것보다 한 화면에 두는 편이 실제 운영 순서에 맞다. 대신 목록이 길어지지 않도록 **연습실·날짜 필터**를 섹션 상단에 뒀다(와이어프레임 원안에는 없던 요소).

- **구현 결과**: 강제취소 버튼은 `reserved` 상태에만 노출한다 — 이미 취소·완료된 예약에는 취소할 것이 없다.
- 관련 기능: F-32
