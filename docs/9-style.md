# 색연필 색소폰 동호회 홈페이지 - 프론트엔드 스타일 가이드

## 0. 문서 개요
본 문서는 와이어프레임(`4-wireframes.md`)이 정의한 14개 화면에 적용할 시각 규칙을 정의한다. `samsungsds.com` 메인 페이지를 브라우저에서 실측해 그 구조를 참조 기준으로 삼되, 이 프로젝트의 규모(1인 개발, 회원 500명 이하)와 PRD의 "별도의 디자인 시스템/컴포넌트 라이브러리 신규 구축 없이 실용적인 최소 UI"(PRD §7) 제약에 맞게 축소해 옮겼다.

**이 문서는 CSS 변수 묶음과 몇 가지 규칙이다. 컴포넌트 라이브러리 명세가 아니다.** 컴포넌트를 미리 만들지 않고, 화면을 만들 때 아래 토큰을 쓰는 것으로 일관성을 확보한다.

## 1. 참조 대상 실측값

`samsungsds.com/kr/index.html`을 Chrome에서 열고 `getComputedStyle`로 측정한 값이다(뷰포트 1274px, DPR 1.5). 인상이 아니라 실제 값이므로 근거로 남긴다.

| 항목 | 실측값 |
|---|---|
| 폰트 | `"Noto Sans", sans-serif` |
| 루트 폰트 크기 | `html { font-size: 10px }` (1rem = 10px 관례) |
| 본문·UI 글자 크기 | 11 / 12 / 13 / 14 / 16 / 18px에 집중, 히어로 79.6px |
| 글자 굵기 | 500(최다) / 400 / 700 / 300 |
| 자간 | **음수이며 크기에 비례**: 본문 -0.02em, 소제목 -0.03em, 히어로 -0.045em |
| 텍스트 색 | `#000`, `#666`, `#888` — 무채색 3단 |
| 배경 | `#fff`, `#f7f8f9`(근백색 표면), `#000`(강조 섹션) |
| 강조색 | `rgb(20,40,160)`(브랜드 네이비), `rgb(33,137,255)`, `rgb(23,120,234)` |
| 강조 틴트 | `rgba(36,85,197,0.04)` — 4% 극연한 배경 |
| 모서리 반경 | 10 / 12 / 18 / 20px, `100px`(알약), `50%`(원형) |
| 콘텐츠 최대 폭 | 약 1260px |
| 테두리 | 1 device px 헤어라인(DPR 1.5에서 0.667px로 계산됨) |

### 관찰된 구조

- **무채색이 지배하고 강조색은 좁게 쓴다.** 강조색이 쓰인 요소는 전체의 1% 미만이고 링크·버튼·지표에만 나타난다.
- **카드가 기본 단위다.** 근백색 배경 위에 흰 카드를 얹고 모서리를 12px 내외로 굴린다. 그림자보다 색 대비로 층을 만든다.
- **한글 본문에 음수 자간을 쓴다.** 한글은 글자폭이 일정해 기본 자간이 넓어 보이므로, 크기가 커질수록 더 조인다.
- **여백이 정보 구획을 만든다.** 구분선 대신 여백으로 섹션을 나눈다.

## 2. 가져온 것과 가져오지 않은 것

**가져온 것**: 무채색 지배 + 단일 강조색 구조, 근백색 표면 위 흰 카드, 크기 비례 음수 자간, 여백 기반 구획, 알약형 보조 버튼, 12px 내외 모서리, 1200px대 콘텐츠 폭.

**가져오지 않은 것**:

- **브랜드 네이비 `#1428A0`은 쓰지 않는다.** 이 값은 삼성의 브랜드 색이다. 그대로 쓰면 무관한 동호회 사이트가 특정 기업의 브랜드를 차용하는 셈이 되므로, 아래 §3에서 별개의 강조색을 정의한다. **로고·서체 자산·문안·이미지도 가져오지 않는다.** 참조한 것은 배치와 수치 체계뿐이다.
- **`html { font-size: 10px }`은 따르지 않는다.** rem 계산은 편해지지만 브라우저 기본 글자 크기를 바꿔 쓰는 사용자의 설정을 무시하게 된다. 아래 토큰이 이미 크기를 정하므로 10px 트릭이 필요하지 않다.
- **검은 배경 강조 섹션, 히어로 79px, 캐러셀, 메가 메뉴.** 홍보 사이트의 장치다. 와이어프레임 2번 홈 화면은 "환영 문구 + 바로가기 2개"로 이미 확정돼 있다(`4-wireframes.md` 2번).

## 3. 색상

```css
:root {
  /* 무채색 — 화면의 90%는 이 안에서 해결한다 */
  --color-text:        #1A1A1A;  /* 본문·제목 */
  --color-text-muted:  #5C6370;  /* 작성자·날짜·조회수 등 메타 */
  --color-text-subtle: #8A9099;  /* 비활성, 플레이스홀더 */
  --color-surface:     #FFFFFF;  /* 카드·표 배경 */
  --color-bg:          #F7F8F9;  /* 페이지 배경 (참조 사이트의 근백색) */
  --color-border:      #E3E6EA;  /* 표 구분선, 카드 테두리 */

  /* 강조 — 링크, 주요 버튼, 선택 상태에만 */
  --color-accent:       #2563A8;
  --color-accent-strong:#1B4A80;              /* hover/active */
  --color-accent-tint:  rgba(37,99,168,0.06); /* 선택된 행·슬롯 배경 */

  /* 상태 — 예약/등급/오류 표시에 필요한 최소 3색 */
  --color-danger:  #C0392B;  /* 오류, 취소, 삭제 */
  --color-success: #2E7D52;  /* 예약 완료, 저장 성공 */
  --color-warning: #B26A00;  /* 등급 미달 안내, 확인 필요 */
}
```

**명암비는 계산해서 골랐다**(흰 배경 기준, WCAG 대비식):

| 조합 | 명암비 | 판정 |
|---|---|---|
| `--color-text` #1A1A1A | **17.4** | 본문 가능 |
| `--color-text-muted` #5C6370 | **6.05** | 본문 가능 |
| `--color-accent` #2563A8 | **6.12** | 본문 가능(링크에 밑줄 없이 색만으로도 읽힘) |
| `--color-accent` on `--color-bg` | **5.76** | 본문 가능 |
| 흰 글자 on `--color-accent` | **6.12** | 버튼 라벨 가능 |
| `--color-danger` #C0392B | **5.44** | 본문 가능 |
| `--color-success` #2E7D52 | **5.03** | 본문 가능 |
| `--color-text-subtle` #8A9099 | **3.22** | **본문 금지** — 큰 글자·비활성 표시에만 |
| `--color-border` #E3E6EA | 1.25 | 장식용. 의미를 색으로만 전달하지 않는다 |

PRD §3은 웹 접근성 표준 준수를 범위 외로 두었다. 위 표는 표준 인증을 목표로 한 것이 아니라, **색을 고르는 데 추가 비용이 들지 않으므로 읽히는 값을 골라둔 것**이다. 다만 `--color-text-subtle`을 본문에 쓰면 실제로 읽기 어려우니 그 한 줄만 규칙으로 지킨다.

강조색 계열을 바꾸고 싶으면 `--color-accent` 3개만 교체한다. 예컨대 색소폰의 황동 느낌을 살리려면 `#8C6A1F` / `#6B5015` / `rgba(140,106,31,0.06)`으로 바꾸면 되고, 나머지 화면은 손댈 필요가 없다 — 토큰을 쓰는 이유가 이것이다.

## 4. 타이포그래피

```css
:root {
  --font-sans: "Noto Sans KR", system-ui, -apple-system, "Malgun Gothic", sans-serif;

  /* 크기 — 참조 사이트의 11~18px 집중 구간을 그대로 따른다 */
  --text-xs:   0.75rem;  /* 12px — 메타정보(작성일, 조회수, 슬롯 시간) */
  --text-sm:   0.875rem; /* 14px — 표 본문, 보조 설명 */
  --text-base: 1rem;     /* 16px — 본문 기본 */
  --text-lg:   1.125rem; /* 18px — 카드 제목, 게시글 제목 */
  --text-xl:   1.5rem;   /* 24px — 화면 제목("게시판 목록", "마이페이지") */
  --text-2xl:  2rem;     /* 32px — 홈 환영 문구 */

  --weight-normal: 400;
  --weight-medium: 500;  /* 참조 사이트의 최다 굵기 — 라벨·버튼 기본 */
  --weight-bold:   700;  /* 제목 */

  --leading-tight:  1.3;  /* 제목 */
  --leading-normal: 1.6;  /* 본문 (게시글 내용) */
}

/* 한글 자간: 크기가 커질수록 조인다 (참조 사이트의 -0.02 ~ -0.045em 관례) */
body                 { letter-spacing: -0.02em; }
h1, h2, .screen-title{ letter-spacing: -0.03em; }
.hero                { letter-spacing: -0.045em; }
```

- **웹폰트는 `Noto Sans KR` 하나만 쓴다.** 굵기는 400/500/700 세 종만 불러온다(300은 쓰지 않음). 로딩 비용을 더 줄이고 싶으면 웹폰트를 빼고 `system-ui` 폴백만 써도 이 가이드는 성립한다.
- 게시글 본문(`4-wireframes.md` 8-2번)만 `--leading-normal`을 쓴다. 표·목록은 `--leading-tight`로 밀도를 유지한다.

## 5. 간격·레이아웃·반응형

```css
:root {
  /* 4px 배수 — 참조 사이트의 인라인 간격(4~8px)과 블록 간격(16px+)을 반영 */
  --space-1: 0.25rem; /*  4px 아이콘-라벨 */
  --space-2: 0.5rem;  /*  8px 폼 라벨-입력 */
  --space-3: 0.75rem; /* 12px 카드 내부 행 간격 */
  --space-4: 1rem;    /* 16px 카드 패딩, 표 셀 패딩 */
  --space-6: 1.5rem;  /* 24px 카드 사이 */
  --space-8: 2rem;    /* 32px 섹션 사이 */
  --space-12: 3rem;   /* 48px 화면 상단 여백 */

  --radius-sm:   8px;   /* 입력창, 배지 */
  --radius-md:   12px;  /* 카드 (참조 사이트 최다값) */
  --radius-pill: 999px; /* 보조 버튼, 등급 배지 */

  --container: 1200px;  /* 참조 사이트 1260px을 이 프로젝트 폭에 맞춰 조정 */
  --nav-height: 56px;
}
```

**브레이크포인트는 하나만 둔다.** 와이어프레임이 PC/모바일 두 가지만 구분하므로(`4-wireframes.md` §1) 그 이상은 만들지 않는다.

```css
/* 모바일 우선. 768px 이상을 PC로 본다 */
@media (min-width: 768px) { /* 표 레이아웃, 가로 메뉴바 */ }
```

| 폭 | 네비게이션 | 표 위주 화면(7·9·11번) | 폼 위주 화면(3·4·5·10번) |
|---|---|---|---|
| < 768px | 햄버거(≡) 접힘 | **행 단위 카드 리스트로 전환** | 1열 그대로 |
| ≥ 768px | 가로 메뉴바 | 표 | 1열, `max-width: 480px` 중앙 |

관리자 화면(12·13·14번)은 모바일에서 표를 카드로 바꾸지 않고 **가로 스크롤**로 둔다(`4-wireframes.md` §1의 결정). 컨테이너에 `overflow-x: auto`만 걸고, 페이지 본문 자체는 절대 좌우로 스크롤되지 않게 한다(FE-02 완료조건).

## 6. 컴포넌트 규칙

미리 만들지 않는다. 아래는 각 요소를 만들 때 지킬 값이다.

| 요소 | 규칙 | 해당 화면 |
|---|---|---|
| **주요 버튼** | 배경 `--color-accent`, 흰 글자, `--radius-sm`, 높이 40px, 패딩 `0 --space-4`, `--weight-medium` | 가입하기, 로그인, 저장, 예약 확정 |
| **보조 버튼** | 배경 투명, 테두리 1px `--color-border`, 글자 `--color-text`, `--radius-pill` | 목록, 취소, 자세히 보기 |
| **위험 버튼** | 글자 `--color-danger`, 테두리 동색, 배경 투명. **삭제·취소는 확인 절차를 먼저 거친다** | 삭제, 예약 취소, 강제 취소 |
| **카드** | 배경 `--color-surface`, `--radius-md`, 패딩 `--space-4`, 테두리 1px `--color-border`. 그림자는 쓰지 않는다 | 모바일 카드 리스트, 홈 바로가기 |
| **표** | 헤더 배경 `--color-bg`, 행 구분선 1px `--color-border`, 셀 패딩 `--space-3 --space-4`, 본문 `--text-sm` | 7·11·12·13·14번 |
| **입력창** | 높이 40px, `--radius-sm`, 테두리 1px `--color-border`, 포커스 시 테두리 `--color-accent`. **포커스 링을 제거하지 않는다** | 3·4·5·8·10번 |
| **읽기 전용 필드** | 테두리 없음, 글자 `--color-text-muted`, 옆에 "(수정불가)" 표기 | 5번 이메일·회원등급 |
| **등급 배지** | `--radius-pill`, 배경 `--color-accent-tint`, 글자 `--color-accent`, `--text-xs` | 6·12번 |
| **잠금 표시** | 자물쇠 아이콘 + `--color-text-subtle` + "접근불가" **텍스트를 함께** 둔다. 색만으로 구분하지 않는다 | 6번 |
| **예약 슬롯** | 가능=`--color-surface`+테두리, 선택=`--color-accent-tint`+테두리 `--color-accent`, 불가=`--color-bg`+글자 `--color-text-subtle`+예약자명 | 9번 |
| **예약 상태** | 예약=`--color-accent`, 완료=`--color-text-muted`, 취소=`--color-text-subtle`. 색과 함께 한글 라벨을 표기 | 11·14번 |
| **오류 메시지** | 입력창 바로 아래, `--text-sm`, `--color-danger`. 서버의 `message`를 그대로 노출한다(백엔드가 사용자 노출 가능한 문구만 4xx에 담는다) | 전 화면 |
| **빈 상태** | 표·목록이 비면 안내 문구 한 줄을 `--color-text-muted`로 중앙 배치 | 7·11번 |

## 7. 적용 방법

토큰은 **파일 하나**에 둔다.

```
frontend/src/styles/tokens.css   # §3~§5의 :root 블록 전체
```

`main.tsx`에서 한 번 import하고, 각 컴포넌트는 `var(--...)`로 참조한다. CSS-in-JS, Tailwind, 별도 테마 프로바이더를 도입하지 않는다(PRD §7, 원칙 §1).

이 자리는 `5-project-principle.md` §6 프론트엔드 디렉토리 구조에 규정되어 있다. 토큰 값과 적용 규칙은 이 문서가, 파일이 놓이는 위치는 원칙 §6이 담당한다 — 새 스타일 파일을 추가할 때는 양쪽을 함께 갱신한다.

### 확정된 화면 시안

화면별로 확정한 시안은 `docs/designs/`에 화면 번호와 같은 이름의 HTML로 보관한다. 와이어프레임(`docs/wireframes/*.svg`)이 **배치**를 정의하고, 이 시안 파일이 **그 배치에 토큰을 입힌 결과**를 정의한다.

| 화면 | 파일 | 확정안 |
|---|---|---|
| 2번 홈 | `docs/designs/02-home.html` | 강조 밴드 — 헤더 아래 `--color-accent-tint` 밴드에 환영 문구, 그 아래 1px 간격 타일 2개 |

시안 파일은 브라우저에서 그대로 열리며, 폭을 줄이면 768px에서 햄버거로 전환되는 것까지 확인할 수 있다. 우하단의 "미리보기 상태" 선택은 **시안 파일에만 있는 장치**로, 비로그인/정회원/운영진 세 상태의 메뉴 차이(FE-02 완료조건)를 코드 수정 없이 보기 위한 것이다. 구현에서는 `features/auth/authStore.ts`의 로그인 사용자·등급이 그 자리를 대신한다.

## 8. 하지 않는 것

- **다크 모드**: 요구사항에 없다(PRD §4에 항목 없음). 토큰을 썼으므로 나중에 `:root` 재정의로 추가할 수 있다.
- **컴포넌트 라이브러리 구축**: Button/Modal/Table을 미리 만들지 않는다. 같은 패턴이 3회 반복된 뒤에 공통화한다(원칙 §1).
- **애니메이션·트랜지션**: hover 색 변화(`transition: background-color .15s`) 정도로 끝낸다. 캐러셀·패럴랙스는 만들지 않는다.
- **아이콘 세트 도입**: 자물쇠(🔒)·화살표(>)·햄버거(≡)는 와이어프레임대로 문자로 표기한다. 아이콘 폰트나 SVG 세트를 새로 들이지 않는다.
- **반응형 브레이크포인트 추가**: 768px 하나로 부족해질 때만 늘린다.
