# E2E 통합테스트 (Playwright)

`docs/3-user-scenario.md`의 S-01~S-08을 실제 브라우저에서 처음부터 끝까지 수행한다.
백엔드 단위테스트(`backend/tests/`)나 프론트엔드 컴포넌트 테스트(`frontend/tests/`)와
달리, **두 앱과 DB가 함께 동작하는지**를 본다.

## 실행

먼저 개발서버 두 개가 떠 있어야 한다. Playwright가 서버를 띄우지 않는다.

```bash
cd backend  && npm run dev     # http://localhost:3001
cd frontend && npm run dev -- --port 5174
```

그 다음:

```bash
cd test
npm test                           # 두 폭 모두 실행 + 리포트 생성
npx playwright test --project=mobile   # 모바일만
npx playwright test --project=desktop  # 데스크톱만
npm run test:headed                # 브라우저를 띄워 눈으로 보며 실행
npm run report                     # 직전 결과로 리포트만 다시 생성
```

## 두 가지 폭으로 돌린다

같은 시나리오를 데스크톱과 모바일에서 각각 수행한다. 전환 기준은 CSS의 768px이며,
그 경계를 사이에 두고 네비게이션(가로 메뉴 ↔ 햄버거)과 목록(표 ↔ 카드)이 바뀐다.

| 프로젝트 | 뷰포트 | 스펙 |
|---|---|---|
| `desktop` | 1280×900 | `01`~`04` |
| `mobile` | 393×851 (Pixel 5, 터치) | `01`~`04` + 모바일 전용 `05` |

`05-mobile.spec.ts`는 모바일에서만 의미가 있는 것을 본다 — 햄버거 펼침/닫힘,
열 제목이 숨고 카드로 바뀌는 전환, 하단에 붙는 선택 요약, 그리고 주요 화면의
**가로 스크롤 0px**(`docs/10-integration-check.md` §4의 실측을 자동화한 것)이다.

## 산출물

결과는 프로젝트별로 나뉜다.

| 파일 | 내용 |
|---|---|
| `e2e/desktop/REPORT.md` | 데스크톱 리포트 (스크린샷 포함) |
| `e2e/desktop/screenshots/` | 데스크톱 화면 캡처 |
| `e2e/mobile/REPORT.md` | 모바일 리포트 (스크린샷 포함) |
| `e2e/mobile/screenshots/` | 모바일 화면 캡처 |
| `e2e/results.json` | Playwright JSON 결과 (리포트의 원재료) |

스펙과 헬퍼는 두 폭이 함께 쓰므로 `e2e/` 바로 아래에 둔다.

## 두 폭에서 함께 도는 스펙을 쓸 때

모바일에서 접힌 메뉴(`.nav__menu`, `.nav__auth`)는 `display: none`이고,
**그런 요소는 접근성 트리에서 빠져 `getByRole`로는 존재조차 찾을 수 없다**
(`toBeAttached`로도 잡히지 않는다). 그래서 인증 상태처럼 두 폭에서 같은 뜻을 가져야
하는 판정은 CSS 선택자와 글자 비교(`.nav__auth`가 "로그아웃"을 담고 있는가)로 한다.
메뉴를 실제로 눌러야 할 때는 `메뉴열기(page)`를 먼저 부른다 — 모바일이면 햄버거를
펼치고, 데스크톱에서는 아무것도 하지 않는다.

## 주의: 개발 DB에 실제로 쓴다

대상이 개발서버이므로 테스트가 만든 회원·게시글·예약이 **개발 DB(`clubhome`)에 남는다.**
운영 DB를 가리키는 서버에는 절대 실행하지 않는다.

- 가입 테스트는 `e2e-<타임스탬프>@example.com` 형태로 매번 새 회원을 만든다(재실행 충돌 방지).
- 게시글·게시판은 테스트가 스스로 지운다. 예약은 이력이므로 남는다(취소 상태로).
- **시드 계정(admin/senior/junior1/junior2)의 등급은 건드리지 않는다.** 등급 변경
  테스트는 시드가 아닌 `user1@example.com`을 쓰고 끝나면 원래 등급으로 되돌린다.
  시드 등급을 바꾸면 그 등급을 전제로 한 다른 검증이 깨진다
  (`docs/10-integration-check.md` §7의 실제 사고 기록).

백엔드 단위테스트는 별도 DB(`clubhome_test`)를 쓰므로 이 테스트와 서로 간섭하지 않는다.

## 이 테스트가 지키는 회귀

기능 확인 외에, 과거에 실제로 났던 버그가 다시 나지 않는지 본다.

- 게시글을 **수정**해도 조회수가 오르지 않아야 한다(상세 재조회로 1→2가 되던 버그).
- 등급 변경 후 "등급을 변경했습니다" 안내가 **보여야** 한다(줄이 remount 되어 안내가
  한 번도 보이지 않던 버그).
- 비연속 슬롯·가운데 슬롯 해제는 거절되고 선택이 그대로 유지되어야 한다.
